# Voice web answers with the local SLM

Unlocked searches open an in-app Google results page. Say "Search for Nifty 50 live price", then tap **Speak summary** to read a short extract of the rendered results aloud. **Stop speaking** cancels playback; **Open in browser** opens the same query externally. This uses the website without a new API integration. Search snippets may be delayed and are not verified live quotes. Consent pages, bot checks, missing readable results, network errors, and unavailable speech are reported. Google can change its page structure, so reading results needs physical-device validation. Page text is treated only as speech content, never as instructions. Playback stops when leaving the page. The previous spoken factual-answer flow continues for locked searches.

Say "Search for what is Kotlin" or "Search Google for Mount Everest". Search now fetches public factual information over HTTPS and reads the selected answer aloud inside Aiko, including the source host. It does not launch a browser or request an unlock. The command SLM can be configured using the existing command-model settings. If model selection is unavailable or invalid, the provider direct factual abstract is read instead; unrelated topics are never selected as a fallback. Both deterministic search commands and validated Tier 2 GOOGLE_SEARCH commands use this flow.

The provider is DuckDuckGo Instant Answers, a key-free, limited factual-answer API, not a full web-results API. It may return no answer for restaurants, weather, current news, or broad queries. A full search provider remains future work. Queries are sent to DuckDuckGo; model inference stays on the device. Internet access is required. No search history is saved by this implementation.

The process-scoped SLM selects an evidence index under its existing inference mutex. The spoken text is copied from that source rather than generated, preventing unsupported model additions. Invalid indices or missing models use a direct-answer fallback when available. Empty results, unavailable direct answers, HTTP errors and timeouts produce spoken failure responses. Untrusted results cannot trigger commands or app launches. Requests are bounded by time and response size, and cancellation propagates.

Locked search uses the existing native system-assistant session and wake-word handoff. Configure Aiko as the default digital assistant and enable the existing wake-word controls as needed. This change does not introduce a new background microphone service. Android/OEM restrictions, screen-off activation, network access under Doze and wake-word behavior must be checked on a physical phone. A locked screen does not by itself guarantee an active listening session.

Restart/rebuild the Android app; Flutter hot reload is insufficient. Device check: configure the SLM, lock the phone, invoke Aiko, say "Search for Mount Everest", and verify the source and answer are spoken without unlocking. Repeat with no internet, no model, an unsupported query, and cancellation.

Provider reference: https://github.com/duckduckgo/duckduckgo-publisher/blob/master/share/site/duckduckgo/api.tx


Weather: Say 'weather in Bangalore' or 'search for weather of Bangalore'. Current conditions are fetched from Open-Meteo using city geocoding, without an API key, GPS permission, browser, or loaded SLM. The spoken report includes the resolved city/country, Celsius temperature, feels-like temperature, conditions and provider timestamp/timezone. Other-date forecasts are not supported. Geocoding selects the first match and speaks its name; specify a country or region to narrow ambiguous city names. General factual answers use at most three sentences as an extractive summary. Provider: https://open-meteo.com/en/docs and https://open-meteo.com/en/docs/geocoding-api .
