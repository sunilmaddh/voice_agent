WHY "CUT, THEN PLAY" NEEDS A DIFFERENT CALL PATH
Once a call disconnects, its audio connection is gone. The intended sequence
must be "decline speaking personally -> a service answers or receives diversion
-> play recording -> hang up". Answering a SIM call through Call.answer does
not give the APK ownership of cellular audio. Default Phone role and local TTS
do not grant remote playback. AOSP's uplink injection is a privileged SystemApi
requiring CALL_AUDIO_INTERCEPTION; hardware support is also conditional [F1].
Speaker-to-microphone playback is not a reliable supported deployment option.

OPTIONS AND RECOMMENDATION
Hosted telephony/IVR - AMBER: preferred candidate for ordinary telephone callers.
A provider can answer its call and play a prerecorded file [F2]. For the exact
interaction, it must coordinate a bounded Accept/Cut decision with the handset:
Accept bridges the user; Cut plays the message and hangs up. This is a proposed
architecture, not present capability. Requires service number or compatible
carrier forwarding, provider eligibility, hosted media/control backend and
internet signalling. Static forwarding alone does not implement the live
Accept/Cut decision. Costs: number rental, inbound minutes, forwarding and
bridged legs, hosting and support; recording/storage only if collecting voicemail.

App-owned VoIP - AMBER: feasible when app/backend owns the media; recorded audio
can be transmitted before hangup. Requires signalling/media stack, background
incoming-call handling, network and NAT/TURN infrastructure. Callers using an
ordinary SIM number need a PSTN gateway/number or forwarding. Costs: backend,
media/TURN bandwidth, managed service fees and PSTN legs/number rental as needed.
Telecom integration does not transfer SIM media ownership to a VoIP application.

OEM-level integration - AMBER in principle, RED for portable APK deployment:
requires OEM/system-image integration, privileged permissions and supported
telephony audio hardware [F1]. Costs: commercial integration/licensing if agreed,
device-specific firmware maintenance and OTA/carrier regression testing.
Default-dialer selection alone cannot enable this route.

Carrier voicemail - AMBER: may provide a custom greeting following supported
diversion. Check SIM carrier availability, reject/busy/no-answer forwarding and
charges. This may satisfy a simpler recorded greeting but does not establish
the exact on-demand agent workflow. Carrier and plan were not supplied.

Recommendation: retain caller announcement/Accept and existing Cut-and-SMS as
the current bounded MVP, with clear wording that Cut sends SMS before rejection.
If prerecorded remote audio is mandatory, evaluate hosted IVR and carrier routing
before implementation. Use VoIP for app-owned calls; pursue OEM work only with a
device partnership. No production-ready full-flow claim is justified yet.
Detailed illustrative provider prices and constraints appear in the appendix.

VALIDATION STILL REQUIRED

EXECUTION AND EVIDENCE
Use a consenting second handset/operator. Record installed APK SHA-256/build,
device model/Android version, carrier and SIM alias, roles, permissions, wake
preferences, voice-friendly-call setting, DND/channel overrides and actual sound
or vibration observed. Keep caller numbers out of the report. Verify the audible
condition really rings; a channel that suppresses sound is not an audible trial.
Start each trial with a new call; set mode before calling. Use Hey Indo and the
complete command "decline the call and text I will call you later". Keep the
specified lock state through completion; record any unlock requirement.
Record activation and recognized command separately from SMS send status.
The caller must check the exact fixed message, sender SIM and receipt timestamp,
and observe the call ending without manually hanging up. On the Aiko handset,
record ringing-to-disconnected evidence and timestamp, not only reject issuance.
Record elapsed time from command end to callback, receipt and disconnect. Observe
SMS for five minutes; if absent, label "not received within observation window",
not permanent delivery failure. Continue recording any later receipt separately.
Use the adjacent CSV once per actual attempt, with evidence references and reasons.
Do not populate unexecuted trials as passes. Summarize completed/attempted counts,
receipt successes, disconnect successes and joint successes for each condition.
GREEN requires all planned trials in the stated scope to show both actual SMS
receipt and actual disconnect, with no wrong recipient/SIM or duplicate actions.
Any failure remains visible; do not discard it because a retry succeeds.

caller hangup/answer before callback, duplicate command, hidden number, permission

app-initiated rejection; distinguish natural caller hangup from app behavior.

SHORT FEASIBILITY RECOMMENDATION (deployment estimates, not selected designs)
Hosted telephony/IVR - AMBER: best candidate if ordinary telephone callers must
hear prerecorded audio. A service can play a recording on a call it terminates
[1]. Requires a service number or supported SIM forwarding, provider account,
regional number eligibility and a hosted webhook/media endpoint. Forwarding and
on-demand control of a currently ringing SIM call are different requirements;
static forwarding does not reproduce the present per-call voice command.
Recurring costs: number rental, inbound minutes, any forwarding/bridged outbound
leg, hosting/media, support and applicable taxes. Get a local carrier/provider
quote before choosing. Twilio's India page lists international numbers from
USD 1.15/month, but no India inbound rate; this does not establish a usable local
India inbound number. Listed outbound India mobile USD 0.0496/min and local
USD 0.0699/min are outbound examples, not IVR inbound prices [2].

App-owned VoIP - AMBER: suitable when calls originate in the app or reach an
app-controlled backend. Control of media makes recorded-audio transmission
feasible (architectural inference); Android ConnectionService integrates an
app's calls with Telecom without granting SIM-call media ownership [3]. Requires
VoIP signalling/media, caller onboarding, network connectivity, background call
handling and NAT/TURN infrastructure. Ordinary SIM callers still require a
PSTN gateway/service number or forwarding. Recurring costs: backend operation,
bandwidth/TURN and optional managed media fees; PSTN legs and number rental add
cost. Twilio browser/app and SIP examples are USD 0.0040/min per applicable leg;
Asia TURN is USD 0.60/GB [2]. These are component rates, not a total project quote.

OEM-level integration - AMBER in principle, RED for ordinary APK deployment:
AOSP uplink injection is a privileged SystemApi, not a default-Phone-role
upgrade [4]. Requires an OEM agreement, system image integration, privileged
permission allowlisting and supported telephony/audio hardware [5]. Confirm
actual device support; allowlisting alone does not guarantee audio routing.
Recurring costs: OEM licensing/support if contracted, device-specific firmware
maintenance, OTA regression testing and carrier charges. No universal public
per-minute API tariff; commercial terms require an OEM quote. High deployment
and maintenance burden makes this unsuitable for a portable APK MVP.

Recommendation: complete SMS-and-decline device validation first. Keep that
architecture if it satisfies the product need. If caller-facing prerecorded
audio is mandatory, evaluate hosted IVR first; use VoIP for app-owned calls,
and OEM integration only with an existing supported device partnership.
No architecture replacement, dependency or application code change made here.
