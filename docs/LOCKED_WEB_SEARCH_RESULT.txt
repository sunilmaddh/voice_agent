WEATHER FIX AND LIMITS
Old code requested count=1 for Bangalore and blindly used the first result;
the recorded workstation match was Bangalore Town, Pakistan. Current code
normalizes the targeted Indian aliases, requests up to ten country-filtered
matches, then checks country/name/state before fetching weather coordinates.
Regression covers Pakistan listed before the valid Bengaluru result and
wrong-country-only rejection. Other ambiguous city names still use the first
provider result; geographic disambiguation is not generally solved.
Weather is fetched online from Open-Meteo current fields with place, update time
and provider timezone spoken. It is numerical-model current conditions, not
guaranteed live station observations. Timestamp freshness and values must be
checked on the phone; source does not enforce a maximum timestamp age.

WHAT THE FREE APPROACH CAN SUPPORT
1. Short factual abstracts where DuckDuckGo Instant Answers has direct evidence,
   with source URL attribution and bounded extractive summaries. No model needed
   for direct abstracts. Coverage and uptime are not guaranteed; no answer means
   a spoken limitation, not an invented answer.
2. Current modeled weather from Open-Meteo for a resolvable city, with the targeted
   Bengaluru correction. Requires internet; tomorrow/yesterday forecasts are
   not implemented in this flow. Unknown locations return a limitation.
3. Native locked-session routing for public lookup is allowed in source; no
   browser intent in current dispatch. Requires the supported system-assistant
   session, microphone/STT/TTS availability and physical locked lifecycle testing.
   The older restricted LockScreenAssistantActivity is a distinct entry point
   whose responder does not permit general search; do not conflate the paths.
Open-Meteo free access is for non-commercial evaluation/prototyping, with rate
limits and no uptime guarantee. Commercial deployment needs a separate service
terms decision; no subscription purchased or integrated [R3].

LIMITATIONS AND DECISION
The lookup is a bounded factual-answer service, not full web search [3]. It did
not meet the current-news or live-share-price requirements in these samples.
Weather has a demonstrated location-selection defect. Network and active native
session are required; screen-off activation, Doze, STT language, TTS voice and
audio routing can affect locked operation. Each HTTP connection has an 8-second
connect/read timeout; the executor has a 60-second deadline. These bounds are
not measured phone response times or a guaranteed user-visible deadline.

Keep general locked web search acceptance OPEN: user-reported answer availability
is 2/5 for any response, but only 1/5 reportedly answered the requested information;
weather failed the live-data requirement. Useful accurate spoken answers without
browser/unlock are not fully
confirmed. Investigate the Kotlin device failure before attributing it to limited
provider coverage, since the same workstation query returned a direct abstract.
Retain the free implementation
for narrow factual use while fixing/validating geographic selection. News needs
dated article evidence and quotes need a dedicated timestamped market-data
source. These gaps do not by themselves establish that a paid provider is needed.
No paid provider was selected, purchased or integrated in this evaluation.
